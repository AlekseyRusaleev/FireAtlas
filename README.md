# Пожарный Атлас

Настольное offline-first приложение для диспетчеров пожарной охраны: поиск водоисточников по KML/KMZ, информационные карточки, карта OpenStreetMap, единый поиск.

## Стек

- **Tauri 2** (Rust) — desktop runtime
- **React + TypeScript + Vite** — UI
- **SQLite + FTS5** — индекс и поиск
- **Leaflet / OpenStreetMap** — локальные пакеты городов

## Быстрый старт

1. Запустите `FireAtlas.exe`.
2. **Настройки** → укажите путь к папке базы → **Сохранить**.
3. Добавьте файлы ИППВ (**Добавить файлы KML / KMZ…** или положите `.kmz` в `FireData/KMZ/`).
4. Положите информационные карточки в `FireData/Информационные карточки/`.
5. **Переиндексировать базу**.
6. Введите город и нажмите **Скачать** (нужен интернет один раз) — карта сохранится локально.

Архив для установки **не содержит** чужой базы, KMZ и меток — только программа и пустой шаблон `FireData`. Настройки, индекс и скачанные карты хранятся на каждом компьютере отдельно (AppData).

## Структура базы на диске

```
FireData/
├── KMZ/                      # .kml / .kmz с ИППВ
└── Информационные карточки/  # папки объектов (docx, pdf, jpg, …)
```

После указания пути приложение создаёт локальный `atlas.db` в AppData. Пакеты карты хранятся отдельно в AppData (`maps/`).

## Возможности

- Импорт KML/KMZ, типы ИППВ (гидрант / водоём / башня / пирс)
- Индекс информационных карточек
- Единый поиск (FTS5) по названию, адресу, номеру, тексту документов
- Локальная карта OSM, поиск адреса с меткой на карте
- **Свои метки на карте** — кнопка «Поставить метку», сохраняются в рабочий KML/KMZ
- Ближайшие ИППВ
- Просмотр JPG, PDF и DOCX; DOC и Visio — через систему
- Избранное и история
- Горячие клавиши: `Ctrl+F` поиск, `F2` карта

## Архитектура дальше (экосистема)

FireAtlas остаётся **локальным** приложением (карта, ИППВ, карточки, метки).  
Адресный поиск выносится на **свой сервер**, чтобы не зависеть от публичных Photon/Nominatim и чтобы его могли использовать другие проекты экосистемы.

### Сейчас (в работе)

1. Self-hosted **Nominatim** на extract **Сибирского федерального округа** (Geofabrik).
2. Отдельный Docker-стек `fireatlas-nominatim-sfo` — **не трогает** текущий проект Infocard.
3. Публичная точка входа: поддомен **`geo.infocardmchs.ru`** → Nginx → контейнер на `127.0.0.1:8088`.
4. В приложении уже есть: адресные подсказки при вводе, строгий адресный сценарий поиска, слой номеров домов из OSM (только там, где в OSM есть `addr:housenumber`).

### Как будет подключаться FireAtlas

```
FireAtlas (клиент)
  ├─ локально: карта OSM, KMZ/ИППВ, информационные карточки, метки
  └─ HTTPS → https://geo.infocardmchs.ru/...
              └─ Nginx → Nominatim (СФО)
```

- Поиск адреса / подсказки — **сервер**.
- Карточки и водоисточники рядом с найденной точкой — **локально**.
- В настройках: город по умолчанию + радиус (км), чтобы не уводить выдачу по всей стране.

### План

| Этап | Что |
|------|-----|
| 1 | Дождаться импорта Nominatim СФО, Nginx + HTTPS на `geo.infocardmchs.ru` |
| 2 | Подключить FireAtlas к своему геокодеру (вместо публичного Photon) |
| 3 | При необходимости — Photon для быстрых подсказок поверх тех же данных |
| 4 | Позже — расширить покрытие (другие округа / Россия) на отдельной мощности |

Ограничения RAM на текущей ВМ (~16 GB) не позволяют комфортно держать всю Россию; СФО — осознанный старт. Диск на Proxmox можно расширять при необходимости.

### Почему не «ближайший дом»

Если точный адрес не найден в индексe — **не подставляем чужой дом**.  
Публичный OSM неполный: номер на тайле и наличие адреса в геокодере — разные вещи. Свой Nominatim по СФО должен дать стабильнее и предсказуемее поиск в регионе.
