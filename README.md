# Пожарный Атлас

Настольное offline-first приложение для диспетчеров пожарной охраны: поиск водоисточников по KML/KMZ, информационные карточки, карта OpenStreetMap, единый поиск.

## Стек

- **Tauri 2** (Rust) — desktop runtime
- **React + TypeScript + Vite** — UI
- **SQLite + FTS5** — индекс и поиск
- **Leaflet / OpenStreetMap** — локальные пакеты городов
- **Свой Nominatim** — `https://geo.infocardmchs.ru` (адресный поиск и крупная нумерация домов)

## Быстрый старт

1. Запустите `FireAtlas.exe`.
2. **Настройки** → укажите путь к папке базы → **Сохранить**.
3. Добавьте файлы ИППВ (**Добавить файлы KML / KMZ…** или положите `.kmz` в `FireData/KMZ/`).
4. Положите информационные карточки в `FireData/Информационные карточки/`.
5. **Переиндексировать базу**.
6. Введите город и нажмите **Скачать** (нужен интернет один раз) — карта сохранится локально.

Архив для установки **не содержит** чужой базы, KMZ и меток — только программа и пустой шаблон `FireData`. Настройки, индекс и скачанные карты хранятся на каждом компьютере отдельно (AppData).

Интернет нужен для: скачивания пакета карты, адресного поиска и крупной нумерации домов (свой геокодер). ИППВ, карточки и уже скачанная карта работают offline.

## Структура базы на диске

```
FireData/
├── KMZ/                      # .kml / .kmz с ИППВ
└── Информационные карточки/  # папки объектов (docx, pdf, jpg, …)
```

После указания пути приложение создаёт локальный `atlas.db` в AppData. Пакеты карты хранятся отдельно в AppData (`maps/`).

## Возможности

- Импорт KML/KMZ, типы ИППВ (гидрант / водоём / башня / пирс)
- Индекс информационных карточек
- Единый поиск (FTS5) по названию, адресу, номеру, тексту документов
- Локальная карта OSM; поиск адреса → метка на карте → карточки по адресу + ближайшие ИППВ
- Подсказки адресов при вводе
- **Крупная нумерация домов** на карте (из своего Nominatim, зум ≥ 15)
- **Свои метки на карте** — кнопка «Поставить метку», сохраняются в рабочий KML/KMZ
- Ближайшие ИППВ
- Просмотр JPG, PDF и DOCX; DOC и Visio — через систему
- Избранное и история
- Горячие клавиши: `Ctrl+F` поиск, `F2` карта

## Свой геокодер

FireAtlas остаётся **локальным** по данным (карта, ИППВ, карточки, метки).  
Адресный поиск и номера домов идут на **свой сервер**, чтобы не зависеть от публичных Photon/Nominatim.

### Что уже работает

| Компонент | Адрес / заметка |
|-----------|-----------------|
| Nominatim | extract **Кемеровской области** (полный СФО на ~16 GiB RAM не влез — OOM / flatnode) |
| Docker | `fireatlas-nominatim-sfo` на ВМ Infocard, отдельно от Infocard |
| Публичный вход | **https://geo.infocardmchs.ru** (Nginx + Let's Encrypt) → `127.0.0.1:8088` |
| Номера домов API | `https://geo.infocardmchs.ru/housenumbers?south&west&north&east&limit` |
| Клиент | сначала свой Nominatim; Photon / публичный OSM — запасной вариант |

Скрипты серверной части: каталог [`server/`](server/) (`housenumbers_api.py`, unit systemd).

Город в **Настройках** только задаёт смещение поиска (центр и радиус), не «включает» геокодер. Покрытие = то, что импортировано на сервере. Новый EXE уже ходит на `geo.infocardmchs.ru` без отдельной настройки.

### Схема

```
FireAtlas (клиент)
  ├─ локально: карта OSM, KMZ/ИППВ, информационные карточки, метки
  └─ HTTPS → https://geo.infocardmchs.ru
              ├─ /search,…     → Nominatim (Кемеровская область)
              └─ /housenumbers → placex (номера домов для подписей на карте)
```

### План дальше

| Этап | Что |
|------|-----|
| ✓ | Nominatim + HTTPS на `geo.infocardmchs.ru` |
| ✓ | FireAtlas → свой геокодер |
| ✓ | Крупная нумерация домов из своего индекса |
| → | Добавить **Новосибирскую область** (для презентации): склеить PBF → импорт без flatnode |
| later | Шире СФО / другие области при большей RAM или отдельной ВМ |

### Почему не «ближайший дом»

Если точный адрес не найден в индексе — **не подставляем чужой дом**.  
Номер на тайле OSM и наличие адреса в геокодере — разные вещи; свой индекс даёт предсказуемый поиск в покрытом регионе.
